## Evidence rules

- Every formal result starts from a clean committed SHA.
- Release preflight separately rejects source-like files outside the Git index,
  including ignored files and CMake-listed headers.
- Development tests on an uncommitted fix are feedback, not release evidence.
- Evidence lives under `artifacts/<full-40-character-commit>/<run-id>/`, never
  only under `/tmp`.
- The final manifest excludes itself and its detached signature, is generated
  only after producers close their files, is signed by the pinned release key,
  and is verified immediately.
- `PREFLIGHT.tsv`, `SUMMARY.tsv`, and `RUN.json` are semantic release records.
  The run record binds exact row counts and hashes; the release receives a
  mode-`0600` receipt and signs `RELEASE_GATE_EVIDENCE.json` into its payload.
- Stable candidate staging additionally requires a signed, commit-keyed
  `RELEASE_CERTIFICATION.json` that references five separately signed typed
  gate directories. Its exact receipt hashes are published through
  `RELEASE_CERTIFICATION_EVIDENCE.json`.
- Stable promotion is a separate metadata-only command. It requires the
  prepublication aggregate plus a separately signed post-publication AppImage
  zsync receipt. That receipt remains in the owner archive because it cannot be
  self-included in the staged asset set whose public URL it proves.
- `not tested`, `tested and failed`, and `tested and passed` remain distinct.
- No metric is called a gate unless a script or workflow enforces it.
- Public artifacts must be byte-for-byte equal to the signed local release set.
  Verification includes a fresh download after the release becomes public; a
  mismatch attempts to return it to draft and fails the release command.
